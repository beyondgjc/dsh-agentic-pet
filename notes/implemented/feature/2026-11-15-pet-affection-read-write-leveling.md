# Agent Note: pet_affection 的读写分级（get 开放 / adjust 限本宠会话）

Status: implemented

English token 行保持原文；正文中文。落地于 0.4.18（commit 3dc203a，2026-11-15，工具面 v2：16→14 合并）。

## Problem

好感账本有两层、两个写者：系统记录**事实**（触摸计数、宠间消息——因果，不是感情），模型维护**判断**（0-100 的好感值，靠调整写回）。合并 `pet_affection_get` / `pet_affection_adjust` 为一个双 op 工具时，必须回答一个权限问题：**谁可以在哪个会话写判断**。外部会话（比如用户的旁路会话、别的工具面）如果拿到 adjust，好感就成了任何人都能刷的分——判断权的归属就是这套系统的可信度。

## Decision

`pet_affection` 一个工具、两个 op，读写分级（[src/driver.ts](../../../src/driver.ts) 的「写权墙」注释处）：

- **`op:"get"` 对所有 pet-preset 会话开放**。返回完整判断上下文：当前值与 mood、系统记录的触摸事实、最近调整与理由、bond（bondDelta 是它唯一的动器）、宠间好感矩阵、剩余配额、时间事实。get 收到任何写字段（delta/reason/toward/bondDelta/bondReason）直接报错——两个形态的参数互相拒绝，不静默忽略。
- **`op:"adjust" 只属于宠物自己的会话**（`voiceOwners.has(exec.agent.id)` 不满足即抛错）。错误信息按「发生了什么 / 为什么 / 下一步」三段写：读当前好感请走开放的 get。
- 判断的纪律原样保留：delta ±3 非零整数 + 必填具体理由；限频（≥5 分钟）、限量（8/天）、限幅（|当日和| ≤ 10）——违规**拒绝并带剩余配额**，不是钳制。驱动永不代替模型移动数值。
- 分级口径与 journal 对齐：journal 的 append 同样只属于宠物自己的会话、read 开放。读写分级是全仓一条纪律，不是一个工具的特例。

## Alternatives considered

- **保留 get/adjust 两个独立工具（16 工具不合并）**——输在每回合注入成本：工具目录是 preset 静态前缀的一部分，本次同批把教学压了 -53% 就是这个动机；且 get/adjust 共享同一份上下文读取，拆开后模型还要做一次无意义的选择。
- **adjust 不设写权墙（全会话开放）**——输在判断权归属：好感是「她」对关系的判断，不是可刷的分；外部会话可写等于把人格层的值交给了任意调用方。journal append 已立「写只属于自己会话」的先例，跟随它而不是另立规则。
- **违规时钳制（clamp）而不是拒绝**——输在教学价值：沉默钳制让模型学不到边界在哪，下次照犯；拒绝带剩余配额的报错本身就是工具教学（driver.ts:3676 注释「宁可报错，不要猜」）。

## Consequences

- 工具目录 16→14；`pet_state` 的好感回读与 get 输出同源，无第二套口径。
- 「参数互相拒绝」成为合并工具的通用纪律：模型传错形就该疼一下（同批的 `pet_schedule_wake` cancel 的 id XOR all:true 防呆同款）。
- 错误信息三段式（发生了什么/为什么/下一步）成为写权墙类拒绝的模板。
- 配额被拒时返回剩余额度——模型能自行规划下次调整时机，不需要重试逻辑。
